# CRTAgent Demo

Небольшой публичный Python-репозиторий для честной демонстрации CRTAgent.
Основной код использует только стандартную библиотеку Python 3.12.
Ветки demo/* содержат намеренные изменения; это не benchmark качества LLM.

## Основной показ

1. В CRTAgent подключите URL этого репозитория и дождитесь клонирования/индексации.
2. Base: `origin/baseline/minimal`. Head: `origin/demo/minimal`. Профиль: `local-quality`.
3. В поле ожидаемого поведения вставьте:

> Скидка при сумме 99 равна 0, при 100 и 101 равна 10; порог включительный.

4. Следите за графом и журналом: Git diff → retrieval → review → аудит кандидатов
   → генерация/аудит тестов → ожидание решения → sandbox → причинная оценка.
5. Проверьте каждый тест и ожидание перед подтверждением. Для скидки нужен вход 100
   и ожидаемое значение 10. Не принимайте тест для 99: он не различает версии.
6. После принятия ожидается PASS/PASS для двух повторов Base, FAIL/FAIL для Head,
   FAIL/FAIL для Base+изменение и PASS/PASS для Head−изменение.
   Точное число найденных гипотез зависит от модели; пропуск не следует скрывать.
7. Раскройте контекст, наблюдения AST, логи повторов, исследуемый diff и хеши сертификата.

Проверенный профиль основного сценария — local-quality (Qwen3.5 4B Q4).
В реальном прогоне он прошёл reviewer, аудит гипотезы, генерацию/аудит теста,
паузу и перезапуск worker, принятие проверенного по спецификации теста и восемь
sandbox-исполнений с confirmed_defect. Local-fast (2B) в первом прогоне
минимального сценария не сформировал замечаний. Это наблюдения на учебном кейсе,
а не общий рейтинг моделей или гарантия повторения результата.

## Дополнительные ветки

Для demo/minimal используется baseline/minimal; остальные demo-ветки сравниваются с main.
Требования и параметры каждого сценария находятся в `demo_plan.json`.

| Base | Head | Что показывает |
|---|---|---|
| `baseline/minimal` | `demo/minimal` | Минимальный живой показ на слабой локальной модели |
| `main` | `demo/discount` | Граничный дефект, контекст policy.py, четыре состояния и сертификат |
| `main` | `demo/verification` | Булева семантика in, различающий вход без маркера, AST-наблюдения |
| `main` | `demo/method` | Ревью методов с квалифицированным именем Class.method |
| `main` | `demo/async` | Async subject и корректное ожидание результата в синхронном pytest |
| `main` | `demo/refactor` | Контроль без дефекта; живой reviewer вправе вернуть пустой список |
| `main` | `demo/intentional` | Смена требования; различие поведения не означает регрессию |
| `main` | `demo/ambiguous-refund` | Причинность при непринятом требовании; в UI принять трактовку или отклонить гипотезу |
| `main` | `demo/environment-error` | Намеренно отсутствующая зависимость; остановка остальных состояний |
| `main` | `demo/flaky` | Реальная случайность: flaky не гарантирован за два повтора |

Расширенный показ: main → demo/full, две независимые регрессии (скидка и verified).
Для verified задайте требование: без ✅ — False, с ✅ — True; тест должен использовать
блок БЕЗ маркера. Первый измеренный живой прогон local-fast на полном наборе
завершился без принятых гипотез; сырые результаты сохранены в CRTAgent. Не обещайте
стабильное нахождение обоих дефектов и не подменяйте ответы модели эталонами.

Дополнительно `demo/coverage` показывает добавленный/удалённый Python-файл,
новый/удалённый символ и неподдерживаемый текстовый diff. Покрытие должно быть явным.

## Решение по неоднозначному требованию

Для `demo/ambiguous-refund` оставьте требование пустым. На входе total=100, fee=10
возможны две политики: возврат 90 с удержанием комиссии или возврат 100 целиком.
Старая версия реализует первую, новая — вторую. Само различие не задаёт правильную политику.
Если система предложила гипотезу, подтвердите её только при выборе удержания комиссии.
Иначе отклоните: причинные тесты отклонённого замечания не должны запускаться.
Текущий UI принимает/отклоняет предложенное ожидание; отдельного редактора новых требований пока нет.

## Состояние и восстановление

Во время ожидания решения обновите страницу: запуск должен восстановиться.
Перезапуск worker в этот момент должен сохранить checkpoint. После принятия граф
возобновляется, а не начинает уже завершённые этапы с нуля. Отмену можно показать
на отдельном запуске; время остановки зависит от текущего ограниченного вызова модели.

## Технические случаи и ограничения

Ветка environment-error намеренно импортирует несуществующую библиотеку. Она
не предназначена для основного показа: модель вправе отказаться создавать такой тест.
Эталонный sandbox-прогон показывает environment_error, не подтверждённый дефект.
Ветка flaky действительно случайна: за два повтора различия могут не проявиться.
Не подменяйте результаты и не обещайте неизбежный статус flaky.

Для воспроизводимой технической проверки в исходном проекте CRTAgent есть команда
`python -m crtagent.showcase verify`. Она использует отдельно написанные эталонные тесты,
реальные sandbox-контейнеры и явно помечает отчёт как authored_oracle_verification.
Это проверка механизма исполнения, а не самостоятельная работа LLM.

Результат запуска можно сохранить из `GET /api/v1/reviews/<run_id>`; события доступны
через `/api/v1/reviews/<run_id>/events`. Отдельного экрана истории/кнопки экспорта
текущая версия UI не обещает. Полный benchmark моделей, автосборка окружений,
Langfuse/Grafana и универсальный анализ всех языков этим демо не имитируются.
